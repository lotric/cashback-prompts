# BRD — «Ядро начисления кэшбэка»

> **Few-shot (смежный финтех-проект):** BRD «Калькулятор бонусов за переводы». Цель — рассчитывать бонус за успешные переводы. Ограничения: валюты RUB/USD/EUR; статусы COMPLETED/FAILED. US-01: как клиент, хочу видеть начисленный бонус. AC: Given перевод COMPLETED, When сумма 1000 RUB, Then бонус 1% = 10 RUB.

## Описание значимости артефакта

| Раздел | Содержание |
|---|---|
| Процесс и контекст использования | Проектирование функциональности «Ядро начисления кэшбэка». Этап сбора и фиксации бизнес-требований — до начала системного проектирования. |
| Цель создания | Зафиксировать бизнес-правила начисления, сторно и выплаты кэшбэка, а также ограничения по лимитам, валютам, комиссиям и статусам транзакций. |
| Что становится определено | Бизнес-сценарии, роли участников, правила расчёта, лимиты (500 000 RUB), поддерживаемые валюты (RUB, USD, EUR), типы комиссий (fixed, percent, none), статусы транзакций (NEW, PROCESSING, COMPLETED, CANCELLED, REFUNDED, FAILED). |
| Пользователи артефакта | Продуктовый аналитик, системный аналитик, архитектор, QA, бизнес-заказчик. Используют как единый источник требований для проектирования и приёмки. |
| Использование в дальнейшем | Основа для Sequence-диаграммы, ER-диаграммы и OpenAPI-спецификации. Используется при написании тест-кейсов и приёмке функциональности. |
| Последствия отсутствия | Разработка начнётся без единого понимания правил. Правила начисления, лимиты и статусы будут трактоваться по-разному, что приведёт к переделкам и расхождениям между командами. |

| Параметр | Значение |
|---|---|
| Проект | Ядро начисления кэшбэка |
| Домен | Финтех, лояльность, расчет вознаграждений |
| Цель | Единый расчет кэшбэка по транзакциям с учетом валюты, комиссии, лимита и статуса |

|---|---|---|---|

## 3. Бизнес-правила

| ID | Правило | Описание |
|---|---|---|
| BR-01 | Валюты | Поддерживаются только RUB, USD, EUR. Иные валюты не рассчитываются |
| BR-02 | Лимит | Максимальная сумма кэшбэка — 500 000 RUB. Для USD/EUR лимит применяется после приведения к RUB |
| BR-03 | Комиссия none | Комиссия = 0. База кэшбэка = сумма транзакции |
| BR-04 | Комиссия fixed | Комиссия = фиксированная сумма. База = сумма транзакции − fixed |
| BR-05 | Комиссия percent | Комиссия = сумма транзакции × процент. База = сумма транзакции − комиссия |
| BR-06 | Статус NEW | Кэшбэк не начисляется |
| BR-07 | Статус PROCESSING | Кэшбэк не начисляется, расчет ожидает завершения |
| BR-08 | Статус COMPLETED | Кэшбэк начисляется |
| BR-09 | Статус CANCELLED | Кэшбэк не начисляется; если уже начислен — сторнируется |
| BR-10 | Статус REFUNDED | Ранее начисленный кэшбэк сторнируется |
| BR-11 | Статус FAILED | Кэшбэк не начисляется; если уже начислен — сторнируется |
| BR-12 | Округление | Суммы округляются до 2 знаков после запятой |
| BR-13 | Идемпотентность | Одна транзакция не может привести к двойному начислению кэшбэка |

## 5. User Stories и Acceptance Criteria

### US-01. Начисление кэшбэка клиенту
**Как** клиент, **я хочу** получать кэшбэк за успешные транзакции, **чтобы** использовать вознаграждение.

**Acceptance Criteria:**
- Given транзакция в статусе COMPLETED, When рассчитан кэшбэк, Then сумма начислена.
- Given транзакция в статусе NEW, PROCESSING, CANCELLED или FAILED, When выполнена обработка, Then кэшбэк не начисляется.
- Given транзакция в статусе REFUNDED, When выполнена обработка возврата, Then ранее начисленный кэшбэк сторнируется.

### US-02. Учет комиссии
**Как** финансовый контролер, **я хочу** видеть расчет кэшбэка с учетом комиссии, **чтобы** контролировать корректность базы.

**Acceptance Criteria:**
- Given тип комиссии none, When рассчитывается база, Then база = сумма транзакции.
- Given тип комиссии fixed, When рассчитывается база, Then база = сумма транзакции − фиксированная комиссия.
- Given тип комиссии percent, When рассчитывается база, Then база = сумма транзакции − процентная комиссия.
- Given расчетная сумма кэшбэка больше 500 000 RUB, When применяется лимит, Then кэшбэк ограничивается 500 000 RUB.

### US-03. Обработка возвратов и отмен
**Как** оператор поддержки, **я хочу** корректно обрабатывать возвраты и отмены, **чтобы** клиент не получал кэшбэк за отмененные операции.

**Acceptance Criteria:**
- Given транзакция была COMPLETED и затем стала REFUNDED, When обрабатывается возврат, Then кэшбэк сторнируется.
- Given транзакция стала CANCELLED или FAILED, When обрабатывается статус, Then кэшбэк не начисляется или сторнируется.

### US-04. Поддержка валют
**Как** продуктовая команда, **я хочу** поддерживать RUB, USD, EUR, **чтобы** клиенты получали кэшбэк в разных валютах.

**Acceptance Criteria:**
- Given валюта RUB, USD или EUR, When выполняется расчет, Then кэшбэк рассчитывается.
- Given валюта не входит в RUB/USD/EUR, When выполняется расчет, Then операция не рассчитывается.
- Given валюта USD или EUR, When проверяется лимит, Then лимит применяется в рублевом эквиваленте.

## 6. Сквозные правила по статусам

| Статус | Начисление кэшбэка | Действие |
|---|---|---|
| NEW | Нет | Ожидание |
| PROCESSING | Нет | Ожидание завершения |
| COMPLETED | Да | Начислить |
| CANCELLED | Нет | Сторно, если было начисление |
| REFUNDED | Нет | Сторно ранее начисленного |
| FAILED | Нет | Сторно, если было начисление |
